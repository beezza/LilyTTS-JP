# LilyBench-JP 自動構築仕様 v0.1

> 目的: 「難読文（Yomi-Hard）」と「アクセント付き文（Accent）」を**人手なし**で作り、**人手なし**で採点する。
> 原則: **正解ラベルは、評価対象のモデル（Yomi / Lily）とは独立した情報源から取る**。同じ仕組みで作った正解と答えを照合しても意味がないため。

---

## 1. 全体像

```
[正解の情報源]                         [難しさで選別]                   [採点]
 ルビ付きテキスト ────┐                                                ┌─ 読み: 候補識別による採点（§4）
 規則で生成した文 ───┼─▶ 複数の情報源で一致したものだけ残す ─▶ 既存手法が間違える文を選ぶ ─▶┤
 人手修正済みの既存ラベル ┤     （高精度の正解だけ）            ＋ ランダムな対照セット     └─ アクセント: 推定器と検出器（§5）
 自然音声と辞書の一致 ──┘
```

各段階の誤り率を自動で推定し（§6）、ベンチマーク自体の信頼区間として報告する。

---

## 2. Yomi-Hard（難読文）の正解の作り方

### 2.1 正解の情報源（独立した4系統）

| 系統 | 情報源 | 得られる正解 | 主な対象 |
|---|---|---|---|
| R1 ルビ | **ノベルゲームのスクリプト内のルビ**、青空文庫のルビ（`｜漢字《かんじ》`）、NHK NEWS WEB EASY のふりがな | 書き手が付けた文脈込みの読み | 同形異音語、難読語、当て字 |
| R2 規則 | 数詞×助数詞の音便表、日付（ついたち、はつか…）、時刻・金額・単位・型番のテンプレート | **規則で一意に決まる読み**（揺れがあるものは許容集合にする） | 数詞・助数詞・記号 |
| R3 読み付き辞書 | Wikipedia 冒頭の「日本橋（にほんばし）」形式、郵便番号データ（住所のカナ読み）、駅名データ | 固有名詞の読み | 地名・駅名・人名 |
| R4 音声 | ゲーム音声と ReazonSpeech の**実際の発話**を、辞書の N-best 候補と照合して取った読み | 人が実際にどう読んだか | 文脈依存の読み全般 |

### 2.2 採用条件（高精度化）

- R1 / R2 / R3 は単独で採用できる。ただし R1 のうち**辞書の候補にない読み**（キャラ名の当て字など）は「固有読み」として別枠にする。
- R4 は、**音素認識器の候補間スコア差（マージン）が大きく、かつ R1 または辞書の候補と一致する**ものだけ採用する。
- **複数の読みが自然な文は除外する**か、許容集合にする（例: 「〜の方」は かた／ほう の両方が成立しうる）。判定は、LLM に「この文脈で他の読みも自然か」を聞き、「自然」と答えたものを落とす。LLM は**正解を作る役ではなく、曖昧な文を落とすフィルタとしてだけ使う**。

### 2.3 難しさで選ぶ

1. 候補の文ごとに、**既存手法**（pyopenjtalk の G2P、ベースの Qwen3-TTS、Irodori-TTS など）の読みを自動で採点する。
2. 既存手法の**1つ以上が誤る文**を「Hard」として採用する。分野（同形異音語・数詞・固有名詞・英字混じり・記号）ごとに上限を設けて偏りを防ぐ。
3. 選別の影響を確かめるため、**選別しないランダムなセット（Random）も同じ数だけ用意し**、両方の結果を報告する。
4. **自分のモデル（Yomi / Lily）は選別に使わない**。使うと、自分が間違えた文ばかり集まって結果が偏るため。

規模の目安: Hard 1,000文 + Random 500文（分野ごとに 150〜250文）。

## 3. Accent（アクセント付き文）の正解の作り方

| 系統 | 情報源 | 信頼度 |
|---|---|---|
| A1 | **JSUT basic5000 の人手修正済みラベル**（jsut-label）。このうち評価用に確保した部分を使い、学習からは除外する | 高 |
| A2 | **辞書・規則と自然音声の一致**: UniDic / OpenJTalk / marine のアクセント予測と、**同じ文を読んだ自然音声**（ゲーム音声・JVS 等）から推定したアクセントが**一致した**アクセント句だけを採用する | 高（一致したものに限る） |
| A3 | 辞書が複数のアクセント型を許すもの（UniDic の aType が複数の語）は許容集合にする | — |

- A2 では、**方言キャラ**（関西弁など）の台詞は除外する。スクリプトの話者情報や LLM による方言判定、推定アクセントと辞書の系統的なずれから自動で検出する。
- 難しさの選別は §2.3 と同じで、既存手法がアクセントを誤る文（複合語・アクセント結合・疑問調・助詞の付き方など）を優先する。
- 規模の目安: 500文（約2,000アクセント句）。

## 4. 読みの自動採点：候補識別による採点

TTS の出力音声について、**対象語をどう読んだか**を判定する。

1. 正解の読みの集合 G と、紛らわしい候補の集合 C（同形異音語の別の読み、助数詞の別の音便形、辞書の N-best）を用意する。
2. **方法1（認識結果の照合）**: カナ音素認識器の出力を、正解の文全体のカナと編集距離でアライメントし、対象語の区間を切り出す。それが G に入るか C に入るかを見る。
3. **方法2（尤度の比較）**: 文のうち対象語だけを候補ごとに差し替えたカナ列を作り、CTC で強制アライメントしたときの尤度を比べる。最も尤度の高い候補が G に属するかを見る。
4. **2つの方法が一致したときだけ「正解」か「誤り」と判定**し、一致しない場合は「判定不能」とする。判定不能の率も報告し、5%を超えたら採点器を見直す。
5. 採点には、**学習時の報酬に使ったものとは別の音素認識器**を使う。例えば w2v-BERT 系のモデルを別途微調整して用意する。

**採点器の検証**: 読みが分かっている自然音声（ゲーム音声のうちルビのある台詞や、JSUT）で、採点の正解率が **99%以上**になることを確かめる。

## 5. アクセントの自動採点

1. **推定器による採点**: 合成音声をモーラ単位でアライメントし、F0 からアクセント句ごとの核の位置を推定する。それが正解の許容集合に入るかどうかで、アクセント句の誤り率を出す。
2. **検出器による採点**（PASQA と同じ考え方）: Lily は PK でアクセントを指定できるので、**同じ文を「正しいPK」と「わざと間違えたPK」で合成**し、アクセントの誤りを検出する二値分類器を学習する。学習には自然音声（正例）も混ぜる。
   - 他のシステムを測るときは、Lily 由来の癖を拾っていないかを確かめるため、**自然音声と他システムの音声で検出器の精度を検証**してから使う。
3. 主指標は推定器によるアクセント句誤り率、副指標は検出器のスコア。

**推定器の検証**: JSUT の評価用部分の人手ラベルと比べて、アクセント核の一致率が **90%以上**であることを確かめる。

## 6. ベンチマーク自体の誤りの自動推定

人手なしでも、**情報源どうしの一致率から正解ラベルのノイズを推定できる**。

- 同じ語について複数の系統（例: R1 と R4、A1 と A2）が重なる部分で一致率を測り、各系統の誤り率を推定する。
- その誤り率を使い、スコアの**信頼区間**（ブートストラップ）と、**ラベルノイズによる上限**（正解ラベルに誤りが p% あれば、正解率は最大でも約 100−p%）を報告する。
- 任意: 30分程度の抜き取り確認（50件）をすれば、推定値を検証できる。必須ではない。

## 7. Zero-shot と Speaker-FT

| セット | 作り方 | 指標 |
|---|---|---|
| Zero-shot | 学習に使っていないタイトルから 50〜100話者を選ぶ。各話者で参照音声1本と、合成する文を4つ（Basic から）選ぶ | SIM、CER、UTMOSv2 |
| Speaker-FT | 学習に使っていない話者のうち、台詞が2時間以上ある 20話者。10分 / 30分 / 2時間の学習用部分と、評価用の台詞（学習用とは別）に分ける | SIM、CER、UTMOSv2、Yomi-Hard / Accent の変化 |

- 評価用の台詞と、その**話者本人の実際の音声**がそろっているので、SIM はその話者の他の台詞（複数）との平均類似度で測る。
- 話者の選び方は自動: 台詞の時間、性別と年齢の推定（話者属性モデル）、方言タグがないことを条件に層別抽出する。

## 8. 学習データへの漏洩を防ぐ

- **作品・文書の単位で分割する**: ゲームはタイトル単位、青空文庫は作品単位、ニュースは記事単位で、評価用と学習用を分ける。
- 評価文と同じ（語, 読み, 前後3語）の組み合わせを、Yomi と Lily の学習データから除外する。
- 評価用ゲームタイトルの**話者（声優）が学習データに出てきてもよい**。ただし Zero-shot 評価には、学習に出てこない話者を使う。

## 9. 出力形式

```
bench/data/
  yomi_hard.jsonl   {id, text, targets:[{span, gold:[...], confusers:[...]}], category, source, split:"hard"|"random"}
  accent.jsonl      {id, text, pk_gold, phrases:[{span, nucleus_allowed:[...]}], source}
  basic.jsonl / zeroshot.jsonl
bench/reports/<system>/<date>.json   各指標・信頼区間・判定不能率
```
